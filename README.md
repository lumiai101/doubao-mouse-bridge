# 豆包鼠标语音适配

让 Logi Options+ 发出的模拟快捷键能够触发豆包输入法语音。更换快捷键时，只改豆包和 Logi Options+ 的正常设置，不改代码、不重启适配程序。

这是一个非官方 Windows 工具。0.1.0 在一台 Windows 10 电脑完成实体鼠标验收；当前 0.1.1 是故障恢复修复版，已完成自动回归，尚未完成同等范围的实体终验。它不是通用于所有设备的修复补丁。

> 当前仅验证豆包输入法 **v0.9.2.7**、配置 schemaVersion **12**。每次创建语音子进程时会校验本机 `rpc.dll` 的 SHA-256；接口不匹配时拒绝启用该次语音。后台模式的错误主要查看日志。不要为绕过检查而直接替换哈希。

## 能做什么

- 只读获取豆包长按和免按快捷键，配置保存后自动重载。
- 通过豆包自己的本地接口启动、停止语音，文字由豆包上屏。
- 匹配模拟键事件，实体键盘事件不被本程序拦截。
- 实体按键始终透传。长按组合持续约 0.6 秒后，若豆包尚未启动录音，尝试补启动；短按不触发兜底。
- 语音接口放在临时子进程内，正常结束后释放连接；键盘回调不再同步写日志。
- 提供暂停、恢复、退出、后台运行和单实例保护。
- 不安装驱动、不修改豆包或罗技文件、不自动创建登录启动项。

本程序**不能识别模拟事件来自哪只鼠标**。其他宏程序发出的相同模拟快捷键也可能触发语音。它也不能替你解决系统或应用的快捷键冲突。

## 安装与运行

需要 Windows x64、已经安装并能正常使用的豆包输入法、Logi Options+，以及 [uv](https://docs.astral.sh/uv/getting-started/installation/)。

1. 下载源码 ZIP 并解压，或克隆仓库。
2. 双击 `setup.cmd`。脚本在本目录创建 `.venv`，安装 pynput 1.8.2 和 six 1.17.0；缺少 Python 3.13 时，uv 按自身配置获取解释器。此步骤需要联网。
3. 双击 `start.cmd`。出现“豆包鼠标语音适配”窗口后，核对它显示的快捷键。
4. 在豆包 **语音输入 → 长按模式** 中选择无冲突组合，再到 Logi Options+ 把对应鼠标键设为相同组合。若豆包区分左右修饰键，必须对应一致。
5. 聚焦普通文本输入框，确认当前使用豆包输入法。长按模式按住说话、松开结束；若配置的是免按模式，则按一次开始、再按一次结束。

例如可以先测试左 Alt+K，再在双方设置中换为左 Alt+J。这只是验收示例，程序没有把这两组按键写成触发常量。

不要同时运行其他豆包语音桥接程序。本程序的单实例锁只防止自身重复运行。

### 已有 Python，不使用安装脚本

推荐 Python 3.13 x64，包含 tkinter。标准 `python.org` Windows 安装包可提供 tkinter。

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -B -I src\doubao_mouse_bridge.py
```

`setup.cmd` 不依赖 pip，使用 uv 安装依赖。手动命令则要求 Python 环境包含 pip。

## 换键与退出

更换快捷键时，在豆包和 Logi Options+ 中保存相同组合。控制窗会更新显示，不需要编辑脚本或重启。

点击 **暂停** 暂停适配，点击 **恢复** 重新读取设置。点击 **退出** 卸载监听，并尝试收尾本程序启动的语音。最小化窗口不会退出。

**“已停用”或窗口关闭不保证豆包录音已停止。** 如果出现启停、取消错误或异常退出，检查豆包语音界面及系统麦克风使用提示，必要时在豆包中手动结束录音。确认停止前，不继续谈论敏感内容。

程序没有可靠的逐会话身份校验。适配运行期间，不通过其他入口或工具另开语音，避免旧的会话标记影响新会话。

### 后台运行、停止与登录启动

在仓库目录的终端运行：

```powershell
.venv\Scripts\pythonw.exe -B -I src\doubao_mouse_bridge.py --background
.venv\Scripts\python.exe -B -I src\doubao_mouse_bridge.py --stop
```

第一条命令隐藏控制窗并在后台监听，第二条只发送退出请求，不证明实例已退出或豆包已停止录音。0.1.0 不支持这个退出请求，升级前需在旧控制窗退出。

默认不会随登录启动。需要自启动时，在 Windows 的当前用户启动文件夹中创建指向 `.venv\Scripts\pythonw.exe` 的快捷方式，参数设为 `-B -I "仓库完整路径\src\doubao_mouse_bridge.py" --background`。使用源码实际所在路径。若 Logi Options+ 登录后没有运行，也需通过软件设置或启动文件夹启动它；仅有桥接程序不能替代罗技按键后台。

登录启动是本机可选设置，不随仓库上传。停用时删除自己创建的启动快捷方式，再发送退出请求。未配置自启动时，重启后需重新运行 `start.cmd`。工具不自动启动豆包，也不自动切换输入法。

## 验证范围

2026-10-19 的 0.1.0 验收覆盖实体鼠标长按启停、文字上屏、运行中换键及普通键鼠输入。2026-10-20 在加入最终长按兜底前，实体鼠标免按路径已确认恢复；最终修复版通过 34 项离线测试，并完成鼠标与键盘回调交替 3 轮、共 6 段真实豆包识别上屏的自动验证。

该回放不是实体硬件按键。最终修复版的实体右 Alt、重启登录和长期稳定性尚未完成验证，旧版本的实体成功不能替代新版终验。其他电脑、其他豆包版本及 Windows 11 也没有本次端到端验收。

仓库内的 34 项离线测试不会录音、注入全局按键或创建监听钩子。测试包含原有逻辑、回调等待、长按兜底状态机及一项静态生命周期约束，不证明全部真实会话边界安全。

```powershell
python -X utf8 -B -I -m unittest discover -s tests -p "test_*.py" -v
python -B -I scripts\check_release.py
```

GitHub Actions 配置只执行离线逻辑测试及发布文件检查。它不代表 GitHub 已经跑过，也不代表真实语音验收。

## 隐私与限制

程序只读 `%APPDATA%\DoubaoIme\conf\config.json`，不上传该文件。运行日志写在 `src\doubao_mouse_bridge.log`，记录接口状态、快捷键设置和进程编号，不主动记录识别正文或音频。父进程和语音子进程都向该路径写日志，各自配置 1 MiB、两份轮转备份；这不是跨进程安全轮转或总大小的严格保证。日志及 `.log.1`、`.log.2` 可能包含本机路径，反馈前须一起脱敏。

本程序没有自己的录音、识别服务、网络请求、剪贴板或文字注入逻辑。语音由豆包处理，其数据行为以豆包的隐私政策为准，**不等于离线识别**。

豆包接口并非公开稳定 API。升级可能使工具停用；已有录音、跨权限窗口、不同输入法状态或应用焦点变化也可能影响工作。不要在密码框或其他敏感输入框内试用。
