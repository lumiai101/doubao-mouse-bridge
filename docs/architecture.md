# 实现原理与接口边界

## 为什么需要桥接

问题表现为同一个快捷键在实体键盘或其他输入法下可用，但 Logi Options+ 发出的模拟键不能触发豆包语音。本机曾测试直接模拟按键和工具栏入口，未解决问题。尚未通过豆包官方源码证明其拒绝模拟事件的具体原因，因此不把“豆包必定过滤 injected 标志”作为已确认根因。

本工具不让系统把模拟键伪装成硬件事件。它监听模拟快捷键，匹配豆包当前设置后，直接请求豆包自己的本地语音会话。

## 运行流程

```text
Logi Options+ 发出模拟组合键
    ↓
pynput 的 Windows 键盘事件过滤器
    ↓
只匹配豆包配置中的快捷键，检查输入法及前台状态
    ↓
InputState 处理长按、免按、重复及松开
    ↓
队列中的工作线程通过管道请求临时语音子进程调用 rpc.dll
    ↓
豆包录音识别，豆包自己的输入法路径上屏
```

配置来源为当前用户的 `%APPDATA%\DoubaoIme\conf\config.json`。文件时间或大小改变时重新读取；不维护第二份用户快捷键配置。

## 代码边界

`src/doubao_mouse_bridge.py` 中的主要符号如下。

| 符号 | 职责 |
|---|---|
| `decode_shortcut`、`read_bindings` | 解析并验证已支持的配置格式 |
| `Shortcut`、`Bindings` | 表示主键、左右修饰键与语音模式 |
| `InputState` | 纯逻辑按键状态机，可离线测试 |
| `PhysicalHold` | 实体长按兜底状态机，不消费实体键 |
| `DoubaoProfile` | 使用 Windows TSF 查询输入法状态 |
| `NativeVoice` | 子进程内的 DLL、命名管道、会话标记及启停 |
| `VoiceSession`、`native_session` | 父子进程通信、接口等待上限和原生资源释放 |
| `main` | 单实例、退出事件、pynput、tkinter、队列和设置重载 |

通用键盘监听复用 pynput，解析、线程和队列使用 Python 标准库。没有另写驱动、录音引擎或识别服务。

## 模拟键和实体键盘

过滤器以 Windows 事件标志识别模拟事件，不辨别设备品牌。只有匹配配置的模拟触发事件才可能被消费，实体键盘事件不被本程序消费。实体修饰键参与冲突判断。

实体长按组合持续约 0.6 秒后触发兜底检查。如果豆包已录音则不另开会话。短按不补启动，按住期间出现额外普通键会阻止本轮兜底，直到全部松开。普通键事件先入队，修饰键和长按主键仍需短暂持锁；这不是所有回调均无等待的保证。

本程序不安装鼠标钩子。其他鼠标按键和滚轮由系统及罗技软件处理。模拟长按路径约等待 200 毫秒，且有 180 秒逻辑上限；实体兜底没有该时长上限，依赖松开、焦点变化、暂停或退出收尾。这些等待不代表端到端延迟。

免按逻辑与豆包原生“任意键结束”并非完整等价。模拟普通键可结束模拟免按会话；实体普通键主要用于阻止长按误启动，仍可能由豆包自行结束录音。验收版本及模式见兼容性文档。

键盘回调不写日志。前台设置窗口判断使用 `OpenProcess` 和 `QueryFullProcessImageNameW`，按前台进程缓存，不再反复运行 `tasklist`。

## 本地接口

`NativeVoice` 动态加载用户已经安装的 `rpc.dll`，仓库不分发 DLL。命名管道为 `\\.\pipe\ObricIme\oime-server`。该路径及 TSF GUID 是程序接口标识，不是用户凭证。

本机观测的 `RpcPipe_SimpleMessage` 用法如下。名称描述本项目用途，不代表豆包的公开 API 契约。

| 代码 | 本项目用途 |
|---|---|
| 1006 | 查询语音状态，0被视为idle |
| 1004 | 激活语音会话 |
| 1007 | 启动链的一步 |
| 1012 | 带参数1完成启动链 |
| 1008 | 停止录音并等待处理 |
| 1013 | 取消本程序持有的会话 |

启动还调用两参数 `RpcPipe_FocusIn`，第二参数为空，并注册语音子进程的 TSF 通知窗口。正常收尾时调用 `RpcPipe_FocusOut` 并注销通知。文字上屏交给豆包，本程序不通过剪贴板或按键合成粘贴识别结果。常驻监听主进程不直接创建 `NativeVoice`。

## 失败与恢复

启动前发现非空闲语音时拒绝启动。`owned` 只表示本程序此前启动过语音，不是逐会话身份校验。若豆包通过其他入口结束了旧会话，再开启新会话，旧标记可能让本程序随后取消新会话。运行期间不要混用其他语音入口，不能保证隔离其他来源的会话。

命令失败、配置异常、输入法不匹配时禁用新触发，不自动重试启动请求。停止后最多等待约15秒观察idle，若仍处理则保留旧标记，不主动丢弃识别结果。

配置热重载、暂停和前台变化会请求取消模拟活动会话或停止兜底会话。退出在锁内关闭命令入口并入队收尾，再请求停止监听。每条原生命令等待最多 25 秒，超时会终止语音子进程，但不保证豆包停止录音。适配停用、子进程退出或窗口关闭都不是停止录音的证明，需核对豆包界面及系统麦克风提示。

`owned` 与 `fallback_owned` 都只是本地标记。豆包提前结束旧会话、随后另开语音时，旧标记可能影响新会话。启动前的空闲检查也不能锁住豆包内部状态，不保证跨入口会话隔离。

Windows 命名 Mutex 防止本程序重复启动，命名 Event 接收 `--stop` 请求，但不协调其他语音桥接软件。`--stop` 找不到事件时同样返回，不证明实例已停止。旧版本没有该事件，升级前需退出旧实例。

父子进程各自配置相同路径的轮转日志，尚无跨进程轮转协调。版本检查依赖 DLL 哈希及配置 schema；DLL 在创建语音子进程时检查，不代表所有运行条件兼容。
