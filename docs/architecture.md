# 实现原理与接口边界

## 为什么需要桥接

问题表现为同一个快捷键在实体键盘或其他输入法下可用，但 Logi Options+ 发出的模拟键不能触发豆包语音。本机曾测试直接模拟按键和工具栏入口，未解决问题。尚未通过豆包官方源码证明其拒绝模拟事件的具体原因，因此不把“豆包必定过滤 injected 标志”作为已确认根因。

本工具不让系统把模拟键伪装成硬件事件。它监听模拟快捷键，匹配豆包当前设置后，直接请求豆包自己的本地语音会话。

## 运行流程

```text
Logi Options+ 发出模拟组合键
    ↓
pynput 的 Windows 键盘事件过滤器
    ↓
只匹配豆包配置中的快捷键，检查输入法及前台状态
    ↓
InputState 处理长按、免按、重复及松开
    ↓
队列中的单个工作线程调用本机豆包 rpc.dll
    ↓
豆包录音识别，豆包自己的输入法路径上屏
```

配置来源为当前用户的 `%APPDATA%\DoubaoIme\conf\config.json`。文件时间或大小改变时重新读取；不维护第二份用户快捷键配置。

## 代码边界

`src/doubao_mouse_bridge.py` 中的主要符号如下。

| 符号 | 职责 |
|---|---|
| `decode_shortcut`、`read_bindings` | 解析并验证已支持的配置格式 |
| `Shortcut`、`Bindings` | 表示主键、左右修饰键与语音模式 |
| `InputState` | 纯逻辑按键状态机，可离线测试 |
| `DoubaoProfile` | 使用 Windows TSF 查询输入法状态 |
| `NativeVoice` | 本机 DLL、命名管道、会话所有权及启停 |
| `main` | 单实例、pynput、tkinter、队列和设置重载 |

通用键盘监听复用 pynput，解析、线程和队列使用 Python 标准库。没有另写驱动、录音引擎或识别服务。

## 模拟键和实体键盘

过滤器以 Windows 事件标志识别模拟事件，不辨别设备品牌。只有匹配配置的模拟触发事件才可能被消费，实体键盘事件不被本程序消费。实体修饰键只参与冲突判断。

本程序不安装鼠标钩子。其他鼠标按键和滚轮由系统及罗技软件处理。当前长按判定有约 200 毫秒的逻辑等待；这不是对端到端延迟的承诺。单次活动会话有 180 秒逻辑上限。

免按逻辑与豆包原生“任意键结束”的行为并非完整等价。本程序自身的状态机处理模拟事件；实体普通键不由它发送停止命令，可能仍由豆包自行处理。公开版本只把长按作为已完成实体验收的模式。

## 本地接口

`NativeVoice` 动态加载用户已经安装的 `rpc.dll`，仓库不分发 DLL。命名管道为 `\\.\pipe\ObricIme\oime-server`。该路径及 TSF GUID 是程序接口标识，不是用户凭证。

本机观测的 `RpcPipe_SimpleMessage` 用法如下。名称描述本项目用途，不代表豆包的公开 API 契约。

| 代码 | 本项目用途 |
|---|---|
| 1006 | 查询语音状态，0被视为idle |
| 1004 | 激活语音会话 |
| 1007 | 启动链的一步 |
| 1012 | 带参数1完成启动链 |
| 1008 | 停止录音并等待处理 |
| 1013 | 取消本程序持有的会话 |

启动还调用 `RpcPipe_FocusIn` 并注册本程序的 TSF 通知窗口。文字上屏交给豆包，本程序不通过剪贴板或按键合成粘贴识别结果。

## 失败与恢复

启动前发现非空闲语音时拒绝启动。`owned` 只表示本程序此前启动过语音，不是逐会话身份校验。若豆包通过其他入口结束了旧会话，再开启新会话，旧标记可能让本程序随后取消新会话。运行期间不要混用其他语音入口，不能保证隔离其他来源的会话。

命令失败、配置异常、输入法不匹配时禁用新触发，不自动重试启动请求。停止后最多等待约15秒观察idle，若仍处理则保留旧标记，不主动丢弃识别结果。

配置热重载、暂停和前台变化会请求取消活动会话。退出先停止监听，再串行尝试收尾语音。取消失败可能只留下日志，适配停用或窗口关闭不证明豆包停止录音。用户需检查豆包界面及系统麦克风提示。DLL函数内部没有独立强制超时，服务阻塞时不能保证退出延迟。

Windows 命名 Mutex 防止本程序重复启动，但不协调其他语音桥接软件。版本检查依赖DLL哈希及配置schema，不能证明所有运行条件都兼容。
