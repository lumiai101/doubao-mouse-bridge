# 托盘版验证与使用边界

当前为 v0.2.0-rc.2 源码预览版发布记录，汇总 2026-10-23 至 2026-10-25 的分阶段证据。下文各阶段的“未提交”“未部署”只描述当时状态；当前范围以末尾发布核验及 GitHub 关联 PR 为准。本版不发布安装器，不自动修改登录启动项。

## 使用方式

沿用仓库的 `setup.cmd` / `start.cmd`。首次安装或补齐依赖仅安装到仓库 `.venv`，不要向原有运行目录安装。程序默认进入托盘，点击图标或菜单“打开设置”显示只读控制窗；关闭窗口只隐藏，必须通过“退出”结束程序。已有旧版本在运行时不会重复监听，也不会自动结束旧版本。

依赖：Python 3.13、pynput 1.8.2、six 1.17.0、pystray 0.19.5、Pillow 11.3.0。Pillow 固定版本沿用本机既有组合，并已在独立 Python 3.13 环境安装测试；不表示它是最新版本或已完成安全审计。

## 可重复验证

在安装了依赖的测试环境中运行：

```powershell
python -m unittest discover -s tests -v
python -X utf8 -B -I scripts/verify_tray.py
python -X utf8 -B -I scripts/check_release.py
git diff --check
```

## 一键健康自检 `scripts/doctor.py`

把上述分散的检查串成一条命令，另加运行实例与系统状态核对：

```powershell
python -X utf8 -B -I scripts/doctor.py            # 完整自检（约 12 秒）
python -X utf8 -B -I scripts/doctor.py --quick    # 仅运行实例与配置核对（约 2 秒）
```

汇总 8 项：默认执行单元测试、真实托盘隔离探针、侧键只读配置、发布门禁、运行进程路径、日志健康（最近 200 行无错误/锁存）、豆包安装 RPC 哈希白名单；Startup 启动项指向默认 skip，只有显式加 `--check-startup` 才只读核对。

退出码：`0` = 全部通过或仅有警告；`1` = 存在失败项，不应据此提交新版本。

不覆盖：实体侧键按下→豆包语音条出现→文字上屏、抢焦点观察、当前常驻实例托盘可见性、RPC 在线连通性以及真实注销/重启登录。托盘项只验证隔离实例，RPC 项只检查安装文件哈希，日志项只看最近 200 行；这些都不是运行实例完整健康证明。把脚本全绿当成「实体验收已通过」是错误的。

用户表示目前登录启动稳定，本轮不再安排注销/重启验收；只读核对 Startup 快捷方式不改变这一豁免，也不把它记成真实登录实测通过。

`verify_tray.py` 需要 Windows 桌面会话，运行真实程序 `main()`、Tk 窗口与 pystray 托盘，但替换输入监听、豆包接口和输入法检测，并使用独立命名互斥体、事件和临时配置。它不会抢占现用实例，不安装全局输入钩子，不打开麦克风。结束后自身窗口与托盘线程退出。

该脚本已分别在 Python 3.14.3 与隔离 Python 3.13.12 环境实际通过以下断言：

- 默认主窗口隐藏，托盘完成显示调用；
- 托盘菜单打开真实设置窗口；
- `WM_DELETE_WINDOW` 仅隐藏窗口；
- 独立命名显示事件可恢复窗口；
- 暂停状态更新，恢复后重新检查；
- 空闲重新检查不调用语音接口；
- 退出后模拟监听停止，真实托盘线程终止。

## 2026-10-24 修复匹配快捷键后弹出系统菜单

用户反馈侧键仍弹菜单；此前将其完全归因于双方快捷键不一致、保证对齐后不再弹出的说法缺乏证据，不作为诊断结论。

### 已复现原因与最小修复

真实键盘过滤器会消费匹配快捷键的主键，但此前已透传的 Win/Alt 按下和释放仍交给系统；系统因此可能只看到一次裸 Win/Alt 按键，激活系统界面或菜单栏。这与双方配置是否一致是两个独立问题。

沿用 Windows `SendInput`，只在已接管的模拟组合释放 Win/Alt 时，将无功能屏蔽键 `VK_E8` 的按下、释放和原修饰键释放放在同一批重放，并消费原释放。私有事件标记避免本程序重放再次触发语音或取消会话。没有提前拦截所有修饰键，没有改变实体键盘、孤立释放和未匹配组合的透传规则；没有新增依赖、修改豆包/罗技配置或启动项。发送失败时放行原释放，优先避免修饰键粘住，不保证此时菜单仍能屏蔽。

机制交叉核对：[AutoHotkey 菜单屏蔽文档](https://raw.githubusercontent.com/AutoHotkey/AutoHotkeyDocs/v2/docs/lib/A_MenuMaskKey.htm)。本实现只调用 Windows API，未引入或复制 AutoHotkey 实现。

### 实际验证
